Spring Boot 3 + Vue3 前后端分离 · 通用型 · 手机/电脑友好
核心原则 路由三级标准 标准开发流程 后端规范 前端规范 Bug 修复动作 环境纪律 代码模板索引

1核心原则（不可违反）

1
前后端分离

后端只出 REST API；前端独立工程、独立端口，只走相对路径 /api（经 Vite 代理转发）。

2
路由三级标准

一级 = 布局壳，二级 = 功能分类（分组菜单），三级 = 功能页面。详见第 2 节。

3
界面零技术标识

前端不显示数据库 ID、内部编码；列表/标签/筛选一律用名称（展示名优先，回退登录名）。

4
移动端一等公民

所有列表页 768px 断点双布局（桌面表格 / 移动卡片）。

5
数据一致性

删除主实体必须同事务级联清理关联数据；禁止孤儿记录。

6
安全内建

鉴权在 service 入口；数据权限统一校验；敏感配置脱敏；危险操作二次确认。

7
阶段化交付 + 测试收口

功能完成 ≠ 完成；三层测试通过才算完成。

8
文档即代码

每阶段技术报告进 docs/，随代码同步仓库。

9
参数编码兼容

前端 query 参数二次编码 + 后端容错解码，保证直连/代理两种路径中文参数行为一致。

2路由三级标准（强制结构）

所有管理端功能页面必须遵循：一级路由为布局壳（MainLayout），二级路由为功能分类（分组菜单），三级路由为具体功能页面。

结构定义（以"用户管理"为例，可为任意分类）

/ ← 一级：布局壳（侧边栏+顶栏+内容区） └── admin/user ← 二级：功能分类（分组菜单） ├── /admin/user/member ← 三级：功能页「会员管理」 ├── /admin/user/staff ← 三级：功能页「员工管理」 └── /admin/user/manager ← 三级：功能页「管理员账号」

路由代码标准

// router/index.js —— 二级分类 + 三级功能页
{
  path: 'admin/user',                                   // 二级：功能分类
  component: () => import('../layouts/RouteGroup.vue'), // 分组容器
  children: [
    { path: 'member',  name: 'user-member',
      component: () => import('../views/admin/user/UserMemberView.vue') },
    { path: 'staff',  name: 'user-staff',
      component: () => import('../views/admin/user/UserStaffView.vue') },
    { path: 'manager', name: 'user-manager',
      component: () => import('../views/admin/user/ManagerAccountView.vue') },
    { path: '', redirect: { name: 'user-member' } }     // 默认跳第一个子页
  ]
}
菜单对齐：菜单 key 与路由 name 严格一致；用 developedRoutes 白名单控制菜单可见性（未开发的入口不上线）。

页面复用标准

同一分类下多个三级页面，若 UI 逻辑相同仅数据域不同，必须抽参数化共用组件：

views/admin/user/
├── UserList.vue           # 共用组件：接收 type prop（区分数据域）
├── UserMemberView.vue     # 薄壳：<UserList :type="1" title="会员管理" />
├── UserStaffView.vue      # 薄壳：<UserList :type="2" title="员工管理" />
└── ManagerAccountView.vue # 薄壳：<UserList :type="3" title="管理员账号" />

新增功能时的路由决策

场景决策
全新功能域（如"营销管理"）新建二级分类（分组菜单）+ 若干三级页
已有分类下加页面该分类 children 加一条三级路由 + 薄壳视图
单一页面功能（如"系统设置"）可直接二级路由挂功能页，不必强行分组
同类多功能同构（按类型/角色）三级页面 + 参数化共用组件（禁止复制多份页面代码）

3标准开发流程（每次需求必走）

需求拆解→ 数据库→ 后端→ 前端→ 三层测试→ 技术报告→ 仓库同步
  1. 需求拆解：拆成可测试要点表（# / 要点 / 实现方式），建 todo 清单，完成一项勾一项；
  2. 开发顺序：数据库（sql/init.sql）→ 后端（entity → mapper → service → controller）→ 前端（api 封装 → 共用组件 → 薄壳视图 → 路由 → 菜单）→ 浏览器联调；
  3. 三层测试：接口测试（含权限边界 403 用例）→ 浏览器测试（真实用户路径）→ 回归测试（重跑受影响模块）；
  4. 文档归档：写《阶段N技术报告-主题.md》进 docs/；
  5. 仓库同步：sync.sh（rsync 排除构建产物 + 条件 commit + push）。
回归必测清单：受影响模块既有接口 · 权限边界 403 · 中文/ASCII 搜索（直连/代理两种路径）· 文件上传（若加过滤器）· 之前修过的 Bug 不复发。

4后端规范（Spring Boot 3 + MyBatis-Plus + Sa-Token）

分层与模块化

com.<org>.<project>/
├── common/     # Result / BizException / GlobalExceptionHandler / UserContext
├── config/     # SaToken / CORS / MybatisPlus / Web 资源 / 过滤器
└── module/<领域>/
    ├── controller/   # 按角色拆分：AdminXxx / OwnerXxx / MemberXxx
    ├── service/
    ├── mapper/
    ├── entity/
    └── dto/
层职责禁止
Controller参数接收/校验、调 service、包装 Result写业务逻辑、直接调 mapper
Service鉴权、业务规则、事务、组合查询操作 HttpRequest
Mapper单表 CRUD（BaseMapper）写跨业务 join
Entity表映射直接当 VO 暴露给前端

核心红线

  • 鉴权在 service 入口第一行：UserContext.checkRole(...)；数据权限抽 checkXxxAccess()（归属者只能操作自己的资源，管理员放行）；
  • 统一响应：成功 Result.ok(data)；失败抛 BizException("面向用户的提示")；
  • 关联名称批量 selectBatchIds 建 Map（禁止 N+1）；
  • 列表接口返回名称不返回裸 ID：VO 加名称字段（展示名优先回退登录名，缺失给兜底文案）；筛选入参用 keyword 按名称模糊匹配（先命中 ID 集合再过滤，无命中返回空页）；
  • 多表写必须 @Transactional(rollbackFor = Exception.class)；删除级联清理；不许删除当前登录账号自己；
  • 敏感配置存 system_config：回显脱敏（前4后4打码）、留空跳过（不覆盖）、指纹缓存热更新；默认值放 yml 用 ${KEY:默认} 占位；
  • 外部服务集成（AI/支付/短信等）：统一入口检查开关+配置；429 指数退避（最多 2 次）；超时放宽；降级给业务提示不裸抛堆栈；
  • 建表 SQL 全进 init.sql，字段必带 COMMENT，必备 id/create_time，唯一键 uk_* 索引 idx_*；
  • 文件上传 UUID 重命名；全局过滤器跳过 multipart 请求。

5前端规范（Vue 3 + Vite 多端工程）

工程组织

按用户群拆独立前端工程（UI 库可按端选择，如管理端 Ant Design Vue、用户端 Naive UI），各工程固定独立端口。结构：api/ views/ components/ layouts/ router/ stores/ utils/。

axios 统一封装

// utils/request.js 核心要点
const request = axios.create({
  baseURL: '/api',
  timeout: 15000,
  // 参数二次编码：兼容代理预解码，配合后端容错解码，直连/代理行为一致
  paramsSerializer: {
    serialize: (params) => {
      const parts = []
      Object.keys(params || {}).forEach((key) => {
        const v = params[key]
        if (v === undefined || v === null || v === '') return
        parts.push(`${encodeURIComponent(key)}=${encodeURIComponent(String(v)).replace(/%/g, '%25')}`)
      })
      return parts.join('&')
    }
  }
})
// 请求拦截：附加 Bearer token（localStorage 键按端隔离）
// 响应拦截：解包 {code,message,data}；401 自动登出

核心红线

  • 页面里不直接写 axios，统一走封装实例；接口按后端模块分文件封装；
  • 路由三级标准（第 2 节，最高优先级）；
  • 移动端强制适配：isMobile = window.innerWidth <= 768 + resize 监听（onUnmounted 移除）；桌面表格/移动卡片双布局；弹窗 :width="isMobile ? '92%' : 520"；模板中不直接访问 window；
  • UI 准则：不显示 ID 一律名称；筛选是名称文本搜索框不是 ID 数字框；删除 Modal.confirm 二次确认；当前账号行显示"当前账号"且无操作按钮；列表标配 spin/empty/分页；操作即时 message 反馈；
  • Vite：固定端口 + /api 代理到后端，前端只请求相对路径。

UI 提交前自查清单

检查项要求
ID 暴露列表/标签/详情无任何数据库 ID（一律名称，展示名优先）
筛选控件名称文本搜索框，不是 ID 数字框
路由结构符合三级标准（分类分组 + 功能页）
移动端列表页 isMobile 双布局；弹窗/抽屉宽度自适应
window 访问模板中无直接访问（用 isMobile 响应式变量）
危险操作Modal.confirm 二次确认，文案说明后果
当前账号显示"当前账号"标识且无编辑/删除按钮
列表三件套spin 加载态 / empty 空态 / 分页（pageSize 10 + 总数）

6Bug 修复标准动作

复现→ 定位→ 根因→ 最小修复→ 回归→ 记录
  1. 复现：用最小步骤稳定复现；
  2. 定位：看后端日志确认请求是否到达 → 区分前端 / 代理 / 网关 / 后端；
  3. 根因：写清楚为什么会发生（不是猜）；
  4. 修复：最小改动 + 兼容新旧两种路径；
  5. 回归：修复场景 + 相邻场景（直连/代理、中文/ASCII、普通请求/上传组合）；
  6. 记录：写入当阶段报告（现象→排查→根因→方案）。

7环境纪律

  • 后端从工程根目录启动 jar（静态资源/相对路径依赖工作目录）；
  • 受限网络环境出网给 JVM 加 -Dhttp(s).proxyHost/Port；
  • 排障先看日志再改代码，不凭猜测；
  • 端口规划互不冲突（后端、各前端工程各占一个固定端口）。
铁律：排障先看日志再改代码，不凭猜测下结论。
