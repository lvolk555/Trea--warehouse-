# 后端开发规范（Spring Boot 3 + MyBatis-Plus + Sa-Token）

## 一、分层与模块化

### 1.1 顶层包结构

```
com.<org>.<project>/
├── <Project>Application.java
├── common/          # 全局基础设施（不依赖任何业务模块）
│   ├── Result.java              # 统一响应 {code, message, data}
│   ├── BizException.java         # 业务异常（携带用户可读 message）
│   ├── GlobalExceptionHandler.java  # @RestControllerAdvice 全局兜底
│   ├── UserContext.java          # ThreadLocal 用户上下文 + 角色常量
│   ├── FileUploadController.java # 通用文件上传（UUID 重命名）
│   └── CommonController.java     # 健康检查等
├── config/          # 配置类：SaToken、CORS、MybatisPlus、Web 资源、过滤器
└── module/          # 业务模块（按领域垂直切分）
    ├── user/  course/  exam/  ai/  points/  ops/  stats/  study/
    └── <module>/
        ├── controller/   # 按角色拆分：AdminXxx / TeacherXxx / StudentXxx
        ├── service/
        ├── mapper/
        ├── entity/
        └── dto/
```

### 1.2 分层职责

| 层 | 职责 | 禁止 |
|----|------|------|
| Controller | 参数接收/校验、调 service、包装 Result | 写业务逻辑、直接调 mapper |
| Service | 鉴权、业务规则、事务、组合查询 | 操作 HttpRequest |
| Mapper | 单表 CRUD（MyBatis-Plus BaseMapper） | 写跨业务 join |
| Entity | 表映射 | 暴露给前端当 VO 用（列表页用 DTO/VO 补充名称字段） |

## 二、统一响应与异常

```java
// 成功
return Result.ok(data);
// 业务失败：抛异常，由 GlobalExceptionHandler 统一转 {code:500, message}
throw new BizException("课程不存在或未上架");
```

- 前端依赖 `code === 200` 判定成功、`code === 401` 触发登出，不要破坏该契约；
- 面向用户的错误信息写在 BizException message 里，语气友好、可指导操作。

## 三、鉴权与权限模型

### 3.1 角色常量与登录校验

```java
UserContext.checkRole(UserContext.ROLE_TEACHER);   // service 方法第一行
long teacherId = UserContext.userId();
```

- 角色编码全局统一（如 1 学生 / 2 教师 / 3 管理员）；
- 鉴权放在 **service 层入口**，controller 只做路由；
- Sa-Token 拦截器放行白名单：登录、注册、健康检查、静态文件。

### 3.2 数据权限（防越权）

资源归属校验抽成私有方法统一复用：

```java
/** 教师：仅自己课程；管理员：任意课程 */
private void checkCourseAccess(Long courseId) {
    if (UserContext.role() == UserContext.ROLE_ADMIN) return;
    Course course = courseMapper.selectById(courseId);
    if (course == null || !course.getTeacherId().equals(UserContext.userId())) {
        throw new BizException(403, "只能管理自己创建的课程");
    }
}
```

权限矩阵写成文档（角色 × 可见范围 × 可执行操作），实现与文档对齐。

## 四、查询与事务

- 查询一律 `LambdaQueryWrapper`（类型安全），动态条件用 `eq(condition, field, value)`；
- 分页用 `Page<>(page, size)`，返回 `IPage`；
- **批量取关联名称**：先收集 ID 去重，`selectBatchIds` 一次查出建 Map，禁止循环内单查（N+1）；
- 多表写操作必须 `@Transactional(rollbackFor = Exception.class)`。

### 级联删除（数据一致性）

删除主实体时在同一事务内清理全部关联数据，防止孤儿记录：

```java
@Transactional(rollbackFor = Exception.class)
public void delete(Long userId) {
    if (userId.equals(UserContext.userId())) {
        throw new BizException("不能删除当前登录账号");
    }
    // 依次清理：AI 会话/消息、选课、学习记录、笔记、考试答题/记录、
    //          积分账户/流水/签到/活动/优惠券、评论 ……
    // 最后删除用户本体
    userMapper.deleteById(userId);
}
```

## 五、接口设计规范

- REST 风格路径：`/course/{courseId}/students/{studentId}/progress`；
- 嵌套路由表达归属关系（courseId 下的 students），扁平路径表达独立资源；
- **列表接口返回名称而非 ID**：VO 上加 `studentName`/`courseName`（昵称优先，回退用户名；数据缺失给兜底文案如"课程已下架"）；
- **筛选按名称关键字**：入参用 `keyword`，先模糊匹配名称命中 ID 集合再过滤记录；无命中直接返回空页；
- 演示列表接口（如待批改）返回 `List<Map<String,Object>>` 时也要补齐名称字段。

## 六、外部服务集成（以 AI 为例）

```java
// 1. 总开关 + 配置校验（所有 AI 调用统一入口检查）
private void checkAvailable() {
    if (!systemConfigService.isEnabled("ai_enabled")) {
        throw new BizException("AI 功能已被管理员关闭");
    }
    if (!isConfigured()) throw new BizException("AI 服务未配置，请联系管理员");
}

// 2. 动态配置：配置指纹缓存，改完即时生效无需重启
private OpenAiChatModel resolveModel() {
    String apiKey = systemConfigService.getValueOrDefault("ai_api_key", defaultApiKey);
    String fingerprint = apiKey + "|" + baseUrl + "|" + model;
    if (cachedModel == null || !fingerprint.equals(cachedFingerprint)) {
        /* 重建客户端并刷新缓存 */ }
    return cachedModel;
}
```

集成纪律：
- **限流重试**：识别 429（含被包装的异常），指数退避最多 2 次，耗尽给友好提示；
- **超时放宽**：免费/慢模型流式 120s、非流式 150s；
- **代理兼容**：Reactor Netty 客户端启用 `proxyWithSystemProperties()`；
- **降级路径**：外部服务不可用时给明确业务提示，不裸抛堆栈。

## 七、敏感配置管理

- 敏感配置（密钥/模型/端点）存 `system_config` 键值表，支持管理端修改；
- **回显脱敏**：密钥保留前 4 后 4 位，中间打码；
- **留空不修改**：保存时空值跳过该 key，防止脱敏值回写覆盖真实密钥；
- 默认值放 `application.yml` 并支持环境变量覆盖：`${ZHIPU_API_KEY:默认值}`，代码不硬编码。

## 八、数据库规范

- 建表 SQL 统一维护在 `backend/sql/init.sql`，每表每字段带 `COMMENT`；
- 必备字段：`id BIGINT AUTO_INCREMENT` 主键、`create_time`、（视情况）`update_time ON UPDATE`；
- 唯一键命名 `uk_*`，普通索引 `idx_*`；
- 枚举值用 tinyint + 注释说明含义（如 status: 0 待审核 1 上架 2 下架）；
- 状态机流转在 service 层集中校验（如"驳回后不可直接上架，需重新送审"）。

## 九、Web 配置纪律

- 上传文件用 UUID 重命名落盘，避免中文/特殊字符路径问题；
- 静态资源映射（上传目录）用绝对路径配置，或保证从工程根目录启动；
- 新增全局过滤器注意：跳过 multipart 请求（避免提前消费上传流）；对参数做容错解码时要保证直连/代理两种路径行为一致。
