## 2. 统计聚合：原生 SQL 下沉到 Mapper

### 怎么使用
统计类查询涉及跨表聚合与按日期分组，`LambdaQueryWrapper` 表达力不足，故在 `StatsMapper` 中用 `@Select` 原生 SQL 实现，服务层只做组装与补充维度信息（课程名、题干等）。

典型例子——用户增长按天分组：

```java
@Select("SELECT DATE(create_time) AS day, COUNT(*) AS cnt " +
        "FROM user WHERE create_time >= #{since} GROUP BY DATE(create_time) ORDER BY day")
List<Map<String, Object>> userGrowthDaily(@Param("since") String since);
```

易错题合并统计（练习 + 考试两个来源用 `UNION ALL` 汇总后再分组）：

```java
@Select("SELECT question_id AS questionId, SUM(wrong) AS wrongCount FROM (" +
        "  SELECT question_id, COUNT(*) AS wrong FROM practice_record WHERE correct = 0 GROUP BY question_id " +
        "  UNION ALL " +
        "  SELECT question_id, COUNT(*) AS wrong FROM exam_answer WHERE correct = 0 GROUP BY question_id" +
        ") t GROUP BY question_id ORDER BY wrongCount DESC LIMIT #{limit}")
List<Map<String, Object>> topWrongQuestions(@Param("limit") int limit);
```

### 为什么这样设计
- **为什么不用 Wrapper**：`GROUP BY DATE()`、子查询 `UNION ALL`、`SUM(CASE WHEN)` 这类聚合表达式 Wrapper 无法表达，原生 SQL 是唯一选择；
- **为什么聚合下沉到 Mapper**：让数据库完成聚合（只返回汇总行），避免把全表数据拉到 Java 内存再循环统计，数据量大时内存与网络开销都不可接受；
- **为什么所有查询都带时间或数量限制**：`WHERE create_time >= #{since}`、`LIMIT #{limit}` 避免全表扫描拖慢看板首屏。

### 规避的问题
- 统计接口是读多写少的展示型接口，聚合结果不要求强实时，若后续数据量增大可加缓存或物化统计表，当前阶段保持直查即可。

## 3. 趋势补零：后端补齐缺失日期

### 怎么使用
按天 `GROUP BY` 的 SQL 只返回有数据的日期，缺失日期不会出现在结果里。若直接交给前端折线图，会出现断点。`StatsService.fillTrend` 在后端把结果补齐为连续 N 天，缺失日期填 0：

```java
private List<Map<String, Object>> fillTrend(List<Map<String, Object>> rows, String valueKey) {
    Map<String, Object> byDay = new HashMap<>();
    for (Map<String, Object> row : rows) {
        byDay.put(String.valueOf(row.get("day")), row.get(valueKey));
    }
    List<Map<String, Object>> trend = new ArrayList<>();
    LocalDate start = LocalDate.now().minusDays(TREND_DAYS - 1L);
    for (int i = 0; i < TREND_DAYS; i++) {
        String day = start.plusDays(i).format(DAY_FMT);
        Map<String, Object> item = new LinkedHashMap<>();
        item.put("day", day.substring(5)); // MM-DD 更紧凑
        item.put("value", byDay.getOrDefault(day, 0));
        trend.add(item);
    }
    return trend;
}
```

### 解决什么问题
- **为什么在后端补零而不是前端**：补零逻辑与"回看天数"这一业务口径绑定，放后端可保证学生/管理多个看板口径一致，前端拿到即可直接渲染，无需各自实现一遍；
- **为什么日期格式取 `MM-DD`**：X 轴空间有限，`substring(5)` 去掉年份，14 个刻度不拥挤。

### 面试问答
**Q：按天统计的折线图，某些天没数据怎么办？**
A：SQL `GROUP BY DATE()` 只返回有记录的日期，直接画图会断点。我在后端把查询结果转成 `day -> value` 的 Map，再按固定天数循环生成连续日期序列，缺失的用 `getOrDefault(day, 0)` 补 0。这样前端无需处理空洞，且多个看板共用同一补零口径。

## 4. 角色鉴权：每个看板接口内部校验

### 怎么使用
三个看板接口共用 `/stats` 前缀，但各自在 Service 入口校验角色：

```java
public Map<String, Object> teacherDashboard() {
    UserContext.checkRole(UserContext.ROLE_TEACHER);
    // ...
}
```

教师看板进一步做**数据级隔离**：只统计 `teacher_id = 当前用户` 的课程，易错题也过滤到本人课程的题目，避免教师看到他人课程数据。

### 解决什么问题
- 鉴权放在 Service 而非仅靠路由拦截，保证即使接口被直接调用也无法越权；
- 数据级隔离（教师只看自己课程）是比角色校验更细的一层，防止"角色对了但数据越界"。

## 5. ECharts 集成：按需渲染 + 生命周期管理

### 怎么使用
管理端 `DashboardView` 根据角色动态渲染不同图表集合，用 `ref` 收集图表 DOM，统一 `initChart` 初始化：

```javascript
function initChart(key, option) {
  const el = chartRefs.value[key]
  if (!el) return
  if (charts[key]) charts[key].dispose()   // 重渲染前先销毁，防止实例泄漏
  charts[key] = echarts.init(el)
  charts[key].setOption(option)
}
```

数据加载完成后在 `nextTick` 里渲染（确保 DOM 已挂载），并监听窗口 `resize` 让图表自适应：

```javascript
onMounted(() => { load(); window.addEventListener('resize', handleResize) })
onBeforeUnmount(() => {
  window.removeEventListener('resize', handleResize)
  Object.values(charts).forEach(c => c?.dispose())
})
```

### 为什么这样设计
- **为什么用 `nextTick`**：ECharts 需要真实宽高才能初始化，数据未返回时容器可能尚未渲染，`nextTick` 保证 DOM 更新后再 `init`；
- **为什么 `dispose` 再 `init`**：重复 `setOption` 到旧实例会残留配置，`dispose` 后重建更干净；
- **为什么卸载时 `dispose` + 移除 resize 监听**：防止组件销毁后图表实例与事件监听仍占用内存（内存泄漏），这是 SPA 里图表组件的常见坑。

### 面试问答
**Q：Vue 里用 ECharts 要注意什么？**
A：三点：① 容器要有确定宽高，且等数据/DOM 就绪后再 `init`（用 `nextTick`）；② 窗口 `resize` 时调用 `chart.resize()` 保证自适应；③ 组件卸载时 `dispose()` 实例并移除监听，避免内存泄漏。重渲染前也要先 `dispose` 旧实例，防止配置残留。

## 6. 界面打磨：统一加载态与空状态

### 怎么使用
- **加载态**：所有异步数据视图用 `n-spin`（学生端 Naive UI）/ `a-spin`（管理端 Ant Design Vue）包裹内容区，`loading` 由 `try/finally` 保证一定会关闭；
- **空状态**：列表为空时用 `n-empty` / `a-empty` 给出友好提示（如"暂无完课数据""暂无错题数据"），表格类组件复用其自带空态；
- **图表空态**：图表容器在无数据时降级为 `a-empty`，避免渲染空白画布。

### 解决什么问题
- 统一的加载/空态避免"白屏""undefined 渲染"等糟糕体验；
- `try/finally` 关闭 loading 保证即使接口报错，界面也不会卡在转圈状态。

## 7. 本阶段踩坑记录

| 问题 | 现象 | 解决 |
|------|------|------|
| 课程热度字段不一致 | SQL 返回 `cnt`，前端取 `count` 导致条形图全空 | 后端统一补 `row.put("count", row.get("cnt"))` |
| 教师平均完成度硬编码 | 统计卡固定显示 0 | 前端用 `computed` 对各课程完成度求均值 |
| 趋势图断点 | 缺失日期折线中断 | 后端 `fillTrend` 补零 |
| 图表重渲染残留 | 切换角色后旧图表配置残留 | `initChart` 内先 `dispose` 再 `init` |

## 8. 面试可复述的项目亮点

1. **聚合下沉 + 限制范围**：统计查询交给数据库聚合，且都带时间/数量限制，避免全表扫描；
2. **后端趋势补零**：统一口径补齐缺失日期，前端零处理直接渲染；
3. **双层权限**：接口角色校验 + 教师数据级隔离（只看自己课程）；
4. **ECharts 生命周期管理**：`nextTick` 初始化、`resize` 自适应、`dispose` 防泄漏；
5. **统一加载/空态**：`try/finally` 保证 loading 一定关闭，空列表有友好提示。
