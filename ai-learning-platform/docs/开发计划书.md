# 基于 Spring Boot 与 Vue 的 AI 辅助在线学习平台
## 开发计划书

| 文档信息 | 内容 |
|---------|------|
| 课题名称 | 基于 Spring Boot 与 Vue 的 AI 辅助在线学习平台的设计与实现 |
| 技术栈 | Spring Boot 3 + Spring AI + Vue 3 + Naive UI（学生端）/ Ant Design Vue（管理端）+ MySQL |
| 关联文档 | 《项目设计文档》v1.2 |
| 文档版本 | v1.0 |

---

## 1. 计划概述

### 1.1 项目目标

1. 完成在线学习业务闭环：课程发布 → 选课 → 学习 → 练习 → 考试 → 成绩；
2. 落地三大 AI 亮点功能：AI 智能答疑（SSE 流式）、AI 智能出题、AI 主观题批改；
3. 建成积分激励体系：看课/签到/考试得积分，积分兑换课程；
4. 交付学生端（Naive UI）与管理端（Ant Design Vue）两个独立前端工程及完整后端服务；
5. 完成毕业设计论文与答辩材料。

### 1.2 交付物清单

| 类别 | 交付物 | 说明 |
|------|--------|------|
| 后端 | ai-learning-platform | Spring Boot 3 服务，含 7 大业务模块、20 张数据表 |
| 前端 | ai-learning-student | 学生端工程（Vue 3 + Naive UI） |
| 前端 | ai-learning-admin | 管理端工程（Vue 3 + Ant Design Vue，教师 + 管理员） |
| 文档 | 项目设计文档、开发计划书、接口文档、数据库脚本 | 随开发同步更新 |
| 论文 | 毕业设计论文 | 需求分析、系统设计、实现、测试四大部分 |
| 演示 | 答辩 PPT + 部署环境 | 可在线演示三大 AI 功能与积分体系 |

## 2. 开发阶段计划

整体分为七个阶段，遵循"先骨架、后业务、再亮点、最后运营与收尾"的顺序。

### 阶段一：环境搭建与基础骨架

**目标**：搭建可登录、可鉴权的系统骨架。

| 任务 | 内容 | 完成标志 |
|------|------|---------|
| 开发环境 | JDK 17、Maven、Node 18+、MySQL 8、Redis 7、IDE 配置 | 环境可用 |
| 数据库 | 按设计文档建 20 张表，编写初始化 SQL 脚本与测试数据 | 脚本可重复执行 |
| 后端骨架 | Spring Boot 工程、统一响应封装、全局异常、跨域配置 | 健康检查接口通 |
| 用户模块 | 注册/登录（BCrypt + Sa-Token）、角色区分、个人中心 | 三端可登录 |
| 前端骨架 | 两个前端工程初始化（Vite + 路由 + Pinia + 组件库接入）、登录页 | 登录联调通过 |

**里程碑 M1**：三端均可注册登录，角色权限生效。

### 阶段二：课程管理与学习中心

**目标**：跑通"教 → 学"核心链路。

| 任务 | 内容 | 完成标志 |
|------|------|---------|
| 课程管理 | 教师创建课程、章/节/视频三级结构、封面上传 | 课程可发布 |
| 课程审核 | 管理员审核上架/驳回、课程管理列表（含积分定价字段） | 审核流可用 |
| 课程广场 | 学生端搜索、分类筛选、课程卡片（免费/积分兑换标识） | 广场可浏览 |
| 学习中心 | 视频播放、进度上报、断点续播、完课标记、章节目录 | 进度准确 |
| 选课 | 免费选课 + 积分课程入口（兑换逻辑阶段五实现） | 我的课程可用 |

**里程碑 M2**：教师可发布课程，学生可完整学完一门课并看到进度。

### 阶段三：题库与练习考试

**目标**：建立"课程 → 章节 → 题目"归属体系，跑通"练 → 考"链路。

| 任务 | 内容 | 完成标志 |
|------|------|---------|
| 题库管理 | 单选/多选/判断/简答题录入，强制绑定课程 + 章节，章节 Tab 筛选 | 题目归属清晰 |
| 章节练习 | 按章节抽题、即时判分、解析展示 | 练习可用 |
| 组卷考试 | 试卷绑定课程，按章节 + 题型抽题，限时、答题卡 | 考试可发布 |
| 自动判分 | 客观题判分、成绩记录、排名 | 成绩可查 |
| 错题本 | 错题按课程归类、解析、标记已掌握 | 错题可回顾 |

**里程碑 M3**：学生可完成章节练习与限时考试，成绩与错题自动记录。

### 阶段四：AI 三大亮点功能

**目标**：接入智谱 GLM，实现核心差异化功能。

| 任务 | 内容 | 完成标志 |
|------|------|---------|
| AI 接入 | Spring AI 配置 OpenAI 兼容客户端，密钥走环境变量 | 调通大模型 |
| AI 答疑 | System Prompt + 课程上下文 + 多轮历史，SSE 流式输出 | 打字机效果可用 |
| 会话管理 | 会话列表、新建会话、历史消息加载 | 会话可管理 |
| AI 出题 | 课程 + 章节 + 知识点输入，JSON 格式输出解析，审核入库 | 题目可入库 |
| AI 批改 | 简答题评分（0-10）+ 建议，教师可采纳/改分 | 批改流可用 |
| 降级策略 | 大模型超时/异常的友好提示，不阻断主业务 | 异常可降级 |

**里程碑 M4**：三大 AI 功能全部可演示，异常场景有降级。

### 阶段五：积分系统与管理端运营

**目标**：建成积分激励闭环与管理端完整运营能力。

| 任务 | 内容 | 完成标志 |
|------|------|---------|
| 积分账户 | 一人一户，余额/累计获得/累计消耗 | 账户准确 |
| 积分获取 | 完课 +10、签到 +5、考试及格 +20、AI 提问奖励，每日上限 | 行为触发奖励 |
| 积分明细 | 每笔变动记录（类型/说明/值），分页查询 | 明细可追溯 |
| 积分商城 | 可兑换课程列表、兑换（事务内扣积分 + 自动选课）、防透支 | 兑换闭环可用 |
| 积分规则配置 | 管理员配置奖励值/上限/开关、兑换定价管理 | 规则可调整 |
| 兑换记录 | 管理员查询兑换明细（学生/课程/积分/状态） | 记录可查 |
| 公告/评论管理 | 公告发布/撤回/置顶，评论审核（广告/举报处理） | 运营可用 |
| 用户管理 | 用户列表、启用/禁用、角色调整 | 用户可管理 |

**里程碑 M5**：学生可通过学习赚积分并兑换课程，管理员可完整运营。

### 阶段六：数据统计与界面完善

**目标**：补齐统计看板，整体打磨。

| 任务 | 内容 | 完成标志 |
|------|------|---------|
| 学生看板 | 学习时长、完成度、积分趋势（ECharts） | 图表可展示 |
| 教师看板 | 选课人数、章节完课率、易错题 TOP、学生明细 | 学情可用 |
| 管理看板 | 用户增长、课程热度、AI 调用量、积分发放/兑换统计 | 看板可展示 |
| 界面打磨 | 主题统一、响应式适配、加载/空状态、交互细节 | 视觉一致 |

**里程碑 M6**：三端功能完整，界面达到答辩演示标准。

### 阶段七：测试、部署与论文

**目标**：质量保障与答辩准备。

| 任务 | 内容 | 完成标志 |
|------|------|---------|
| 功能测试 | 核心链路用例测试（登录/学习/考试/积分兑换/AI） | 用例通过 |
| 接口测试 | 关键 API 的边界与权限测试 | 无高危缺陷 |
| 部署 | 服务器部署（后端 + MySQL + Redis + 两个前端），域名/端口配置 | 在线可访问 |
| 论文撰写 | 需求分析、系统设计、实现、测试章节，图表规范 | 论文定稿 |
| 答辩材料 | 答辩 PPT、演示脚本、操作视频 | 材料齐全 |

**里程碑 M7**：系统上线可演示，论文与答辩材料完成。

## 3. 关键技术风险与应对

| 风险 | 影响 | 应对措施 |
|------|------|---------|
| 大模型接口不稳定/限流 | AI 功能无法演示 | 降级提示 + 本地模拟数据兜底；演示前预热接口 |
| SSE 流式跨域/断连 | 答疑打字机效果异常 | 后端统一 CORS 配置，前端 EventSource 重连机制 |
| 积分并发扣减透支 | 数据不一致 | 数据库事务 + 余额校验，必要时乐观锁 |
| 视频存储与播放 | 学习中心不可用 | 初期用外链/对象存储，本地仅存 URL |
| 两个前端工程联调成本 | 进度延误 | 先定接口文档（Apifox/Swagger），前端按 Mock 并行开发 |
| 时间不足 | 功能缩水 | 按 P0 → P1 → P2 优先级裁剪，P2 功能（笔记、部分看板）可降级 |

## 4. 开发规范

| 项 | 约定 |
|----|------|
| 代码管理 | Git 管理，功能分支开发，提交信息说明改动内容 |
| 接口规范 | RESTful 风格，统一响应格式 `{code, message, data}`，先出接口文档再开发 |
| 命名规范 | 后端驼峰、表名下划线；前端组件 PascalCase、文件 kebab-case |
| 注释要求 | 类与公共方法写注释，AI Prompt 与关键算法写清思路 |
| 测试要求 | 核心业务（积分、判分、权限）必须自测通过后提交 |

---

## 5. 优先级裁剪策略

若进度紧张，按以下顺序保障核心功能：

1. **必须完成（P0）**：登录鉴权、课程管理与学习、题库与练习考试、AI 答疑、积分兑换课程；
2. **尽力完成（P1）**：AI 出题、AI 批改、积分任务、管理端运营模块、组卷考试；
3. **可裁剪（P2）**：学习笔记、学生/教师看板细节、公告评论管理、AI 用量统计。

## 6. 总结

本计划以"业务闭环优先、AI 亮点居中、运营与统计收尾"为主线，七个阶段层层递进，每个阶段都有明确的完成标志与里程碑。开发过程中文档随代码同步更新并推送至 GitHub 仓库，保证过程可追溯、成果可展示。
