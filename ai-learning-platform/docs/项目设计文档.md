## 1. 项目概述

### 1.1 项目背景

随着在线教育的普及，高校学生越来越依赖网络课程进行自主学习。然而传统在线学习平台普遍存在以下痛点：

1. **缺乏个性化辅导**：学生遇到疑问只能等待教师答疑，反馈周期长；
2. **教师负担重**：出题、批改作业占用大量重复性劳动时间；
3. **学习过程缺乏跟踪**：学生难以量化自己的学习进度和薄弱环节。

大语言模型（LLM）技术的成熟为解决上述问题提供了可行路径。本项目旨在构建一个融合 AI 能力的在线学习平台，让学生获得接近一对一辅导的学习体验，同时减轻教师的教学负担。

### 1.2 项目目标

1. 构建完整的在线学习业务闭环：课程发布 → 选课 → 学习 → 练习 → 考试 → 成绩；
2. 集成大模型能力，实现 **AI 智能答疑**、**AI 智能出题**、**AI 主观题批改** 三大亮点功能；
3. 建立 **积分激励体系**：学生通过看课、签到、考试等行为获取积分，积分可兑换付费课程，形成"学习 → 激励 → 再学习"的正向循环；
4. 提供多角色权限体系（学生/教师/管理员）与学习数据统计，管理端覆盖课程审核、公告、评论、积分运营等完整运营能力。

### 1.3 课题价值（答辩定位）

> 本系统面向高校在线学习场景，解决传统网课平台"缺乏个性化辅导"的痛点，通过 AI 智能答疑和自动批改，让学生获得接近一对一辅导的学习体验，同时减轻教师的出题和批改负担。

## 2. 需求分析

### 2.1 用户角色分析

| 角色 | 定位 | 使用占比 | 核心诉求 |
|------|------|---------|---------|
| 学生 | 核心使用者 | ~80% | 学课程、做练习、问 AI、赚积分兑课程、看成绩 |
| 教师 | 内容提供者 | ~15% | 建课程、录题库（按章节归属）、AI 出题、看学情 |
| 管理员 | 运营维护者 | ~5% | 审核课程、管理用户、公告/评论管理、积分规则与兑换运营 |

| 类别 | 要求 |
|------|------|

## 3. 系统架构设计

### 3.1 总体架构

采用前后端分离的 B/S 架构，分为四层：

```
┌─────────────────────────────────────────────────┐
│  前端层：Vue 3 + Vite + Ant Design Vue + Pinia    │
│  （课程页面 / 学习播放器 / AI 对话 / 管理后台）       │
├─────────────────────────────────────────────────┤
│  网关/接口层：RESTful API + SSE 流式接口            │
├─────────────────────────────────────────────────┤
│  后端层：Spring Boot 3                            │
│  ├─ 业务服务：用户/课程/学习/考试/统计               │
│  └─ AI 服务：Spring AI → GLM（OpenAI 兼容接口）    │
├─────────────────────────────────────────────────┤
│  数据层：MySQL 8（业务数据）+ Redis（缓存/会话）     │
└─────────────────────────────────────────────────┘
```

### 3.2 技术选型

| 层 | 技术 | 版本 | 选型理由 |
|----|------|------|---------|
| 后端框架 | Spring Boot | 3.2.x | 主流、生态成熟 |
| AI 框架 | Spring AI | 1.0.x | 官方 AI 抽象，支持 OpenAI 兼容接口 |
| ORM | MyBatis-Plus | 3.5.x | 简化 CRUD，代码生成 |
| 鉴权 | Sa-Token | 1.37.x | 轻量，支持多角色权限 |
| 数据库 | MySQL | 8.0 | 关系型业务数据 |
| 缓存 | Redis | 7.x | 登录会话、热点数据缓存 |
| 前端框架 | Vue | 3.4.x | 组合式 API，主流 |
| 构建工具 | Vite | 5.x | 快速热更新 |
| UI 组件库 | Ant Design Vue | 4.x | 企业级组件库，设计规范完善，适合管理端与多角色系统 |
| 状态管理 | Pinia | 2.x | Vue 3 官方推荐 |
| 图表 | ECharts | 5.x | 数据统计可视化 |

## 4. 数据库设计

共 20 张表，覆盖用户、课程、学习、考试、AI、积分、运营七大业务域。

### 4.1 ER 关系概览

```
user ──< course_enrollment >── course ──< chapter ──< video
                                  │
                                  ├──< question（题库，按 课程→章节 两级归属）
                                  ├──< exam ──< exam_record ──< exam_answer
                                  ├──< ai_chat_session ──< ai_chat_message
                                  └──< course_exchange_record（积分兑换记录）

user ──< learning_record（学习进度）
user ──< points_account（积分账户，1:1）──< points_record（积分明细）
question ──< practice_record（练习记录）
points_rule（积分规则配置，全局）
notice（公告）  course_comment（课程评论）
```

## 5. AI 模块详细设计

### 5.1 接入方式

通过 Spring AI 的 OpenAI 兼容客户端对接智谱 GLM，只需修改 base-url 与 api-key：

```yaml
spring:
  ai:
    openai:
      base-url: https://open.bigmodel.cn/api/paas/v4
      api-key: ${ZHIPU_API_KEY}
      chat:
        options:
          model: glm-4-flash
```

### 5.2 AI 智能答疑

**调用流程**：

```
学生提问 → 后端组装 Prompt（System 提示词 + 课程上下文 + 历史对话 + 当前问题）
        → ChatClient.stream() 流式调用
        → SSE 逐字推送到前端 → 打字机效果渲染
        → 完整回答落库（ai_chat_message）
```

**System Prompt 设计**：

```
你是《{课程名称}》课程的 AI 助教。课程简介：{课程简介}。
要求：
1. 只回答与本课程相关的问题，回答准确、简洁、易懂；
2. 如果问题超出课程范围，礼貌说明并引导学生回到课程内容；
3. 涉及代码时使用 Markdown 代码块格式输出。
```

**上下文管理**：每次请求携带最近 10 轮对话历史，保证多轮连贯。

### 5.3 AI 智能出题

**调用流程**：

```
教师输入（所属课程 + 归属章节 + 知识点 + 题型 + 数量）
  → Prompt 要求 AI 以 JSON 数组格式输出题目
  → 后端解析 JSON，校验字段完整性
  → 生成"待审核"题目列表 → 教师逐题审核
  → 通过入库：题目自动归入所选课程的对应章节题库（source=2）
```

**Prompt 关键约束**：输出严格 JSON 格式（题干/选项/答案/解析四字段），便于程序解析。

**归属约束**：题目必须绑定"课程 → 章节"两级归属，组卷时仅能从对应课程题库抽题，保证考试内容与教学内容一致。

### 5.4 AI 主观题批改

**调用流程**：

```
学生提交简答题 → 后端组装（参考答案 + 学生答案 + 评分标准）
  → AI 输出评分（0-10）与改进建议（JSON 格式）
  → 写入 exam_answer（ai_score / ai_comment）
  → 教师可复核改分
```

### 5.5 降级策略

大模型接口超时或异常时，返回友好提示"AI 服务暂时繁忙，请稍后重试"，不影响课程学习、练习等主业务。

## 7. 安全设计

| 措施 | 实现方式 |
|------|---------|
| 密码安全 | BCrypt 加盐哈希，不存明文 |
| 身份鉴权 | Sa-Token JWT，请求头携带 token |
| 权限控制 | 注解式校验（@SaCheckRole），接口级拦截 |
| 参数校验 | JSR-303 注解（@Valid）+ 全局异常处理 |
| SQL 注入 | MyBatis 预编译参数 |
| XSS | 前端渲染转义，富文本白名单过滤 |
| 密钥管理 | AI api-key 存环境变量，不入代码库 |
| 积分一致性 | 积分扣减与兑换记录在同一事务内完成，余额校验防透支，防重复兑换 |
