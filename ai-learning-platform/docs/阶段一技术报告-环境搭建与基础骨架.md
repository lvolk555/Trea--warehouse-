## 2. Spring Boot 3 + JDK 21

### 怎么使用
- 以 `spring-boot-starter-parent` 作为 Maven 父工程统一管理依赖版本，避免手动对版本；
- 通过 `starter` 机制按需引入能力：`starter-web`（REST 接口）、`starter-validation`（参数校验）、`starter-webflux`（为阶段四 SSE 流式输出预留）；
- 主类 `AiLearningApplication` 一个注解 `@SpringBootApplication` 完成自动装配。

### 解决什么问题
- 传统 SSM 项目需要大量 XML 配置（web.xml、spring-mvc.xml、数据源配置），Spring Boot 的自动装配 + 内嵌 Tomcat 让"一个 jar 即一个服务"；
- starter 依赖聚合解决了"手动凑依赖、版本冲突"的问题。

### 规避的问题 / 踩坑记录
- **JDK 23+ 注解处理变化**：高版本 JDK 默认关闭注解处理，导致 Lombok 的 `@Data` 不生成 getter/setter，编译报"找不到 get 方法"。解决方式是在 `maven-compiler-plugin` 中显式配置 `<proc>full</proc>` 并把 Lombok 放入 `annotationProcessorPaths`。
- 如果不用 Spring Boot 而用原生 Servlet，同样的登录接口需要手写过滤器、手动管理线程池、手动打包 war，工作量至少翻三倍，且无法快速对接 Spring 生态（AI、事务、校验）。

## 3. MyBatis-Plus（ORM 层）

### 怎么使用
- 所有 Mapper 继承 `BaseMapper<T>`，零 SQL 获得 CRUD；
- 条件构造使用 `LambdaQueryWrapper`，以方法引用（`User::getUsername`）代替字符串字段名，重构字段时编译期即可发现错误；
- 注册 `MybatisPlusInterceptor` + `PaginationInnerInterceptor` 实现物理分页。

### 解决什么问题
- 毕业设计中表多达 21 张，若用原生 JDBC 或纯 MyBatis，每张表都要写 XML 映射与手写 SQL，重复劳动巨大；
- Lambda 条件构造器解决了"字段名写错要到运行时才报错"的问题。

### 规避的问题 / 踩坑记录
- **分页插件类找不到**：MyBatis-Plus 3.5.9+ 把 `PaginationInnerInterceptor` 依赖的 SQL 解析器拆到了独立模块 `mybatis-plus-jsqlparser`，不额外引入会编译失败。这是版本升级带来的依赖拆分，需要阅读 changelog 才能定位。
- **Boot3 专用 starter**：必须使用 `mybatis-plus-spring-boot3-starter`，旧的 `mybatis-plus-boot-starter` 基于 javax 命名空间，在 Jakarta EE 的 Spring Boot 3 下无法启动。
- 如果不用 ORM 框架：21 张表 × 平均 6 个 SQL = 120+ 条手写 SQL，分页、防注入都要自己处理，SQL 注入风险显著上升。

## 4. Sa-Token（登录鉴权）

### 怎么使用
- 登录：`StpUtil.login(userId)` 签发 Token，`StpUtil.getSession().set("role", role)` 把角色写入会话；
- 鉴权：`SaInterceptor` 拦截器全局拦截，仅放行 `/auth/login`、`/auth/register`、`/common/health`；
- 业务层通过自封装的 `UserContext` 获取当前用户 ID 与角色，`checkRole(...)` 一行完成角色校验。

### 解决什么问题
- 三端（学生/教师/管理员）共用一个后端，需要"登录态 + 角色权限"两层控制；
- Sa-Token 开箱即用，无需像 Spring Security 那样配置过滤器链、UserDetailsService 等大量样板。

### 为什么不用 Spring Security 全家桶
- 本项目权限模型简单（仅三个固定角色），Spring Security 的过滤器链学习成本高、配置冗长；
- 但仍引入了 `spring-security-crypto` 单独使用其 `BCryptPasswordEncoder`——**只取所需模块，不引入整套安全框架**，避免过度设计。

### 规避的问题 / 踩坑记录
- Sa-Token 1.44 移除了 `SaBCryptUtil`，最初按旧教程调用导致编译失败，改为 `BCryptPasswordEncoder` 解决。
- 密码**绝不落明文**：BCrypt 自带随机盐，同一密码每次加密结果不同，拖库后无法反推；如果不用哈希加密，数据库泄露即等于所有用户密码泄露。

## 5. 统一响应 + 全局异常（工程规范）

### 怎么使用
- `Result<T>` 统一封装 `{code, message, data}`，前端拦截器只需处理一种结构；
- `@RestControllerAdvice` 全局异常处理器分类处理：业务异常（BizException）、未登录（401）、无权限（403）、参数校验失败（400）、兜底异常（500）。

### 解决什么问题
- 避免每个 Controller 各自 try-catch、各自拼错误格式，前端不用针对每个接口写不同的错误解析；
- 参数校验用 `@Valid` + `@NotBlank/@NotNull` 注解声明式完成，校验规则与业务代码分离。

### 不用的后果
- 异常直接抛给前端会暴露堆栈信息（安全隐患），且 HTTP 500 与业务错误混在一起，前端无法区分"网络错误"和"用户名已存在"这类业务提示。

## 6. 前端骨架：Vue 3 + Vite + Pinia + 双组件库

### 怎么使用
- **两个独立工程**：`ai-learning-student`（Naive UI）与 `ai-learning-admin`（Ant Design Vue），互不依赖、独立构建部署；
- Vite 作为构建工具，开发环境毫秒级热更新；
- Pinia 管理登录态（`useUserStore`），路由守卫读取 `isLoggedIn` 实现未登录跳转；
- axios 实例统一配置 `baseURL=/api`、请求拦截器附加 `Authorization: Bearer <token>`、响应拦截器解包 `Result` 结构并在 401 时自动登出。

### 为什么拆两个工程而不是一个工程两套主题
- 学生端与管理端面向人群、菜单、权限完全不同，拆分后互不影响打包体积，部署可分别上线；
- Naive UI 风格轻快适合 C 端学习场景，Ant Design 组件丰富（表格/表单/抽屉）适合 B 端管理场景。

### 规避的问题
- 开发环境通过 Vite `proxy` 把 `/api` 转发到后端 8080 端口，**规避浏览器跨域限制**；生产环境由 Nginx 反向代理，前后端完全无跨域问题。
- 如果不用路由守卫：未登录用户可直接通过 URL 访问受保护页面，只能靠后端 401 兜底，用户体验差（先看到空页面再被踢走）。

## 7. 数据库设计（21 张表）

### 怎么使用
- 初始化脚本 `backend/sql/init.sql` 采用 `DROP TABLE IF EXISTS` + `CREATE TABLE` 保证可重复执行；
- 所有表统一 `BIGINT` 自增主键、`create_time` 默认 `CURRENT_TIMESTAMP`；
- 外键关系用逻辑外键（索引 + 应用层校验），不建物理外键，避免分库分表与批量操作受限。

### 关键设计决策
- 用户表 `role` 字段区分三端，一张表支撑三种角色，避免三张用户表的同步问题；
- 金额/分数类字段用 `DECIMAL` 而非 `FLOAT`，避免浮点精度丢失（成绩 89.9 不会变成 89.89999）。

## 8. 面试问答要点（本阶段）

**Q：为什么选 Sa-Token 而不是 Spring Security？**
A：项目只有三个固定角色，权限模型简单。Sa-Token 登录、会话、拦截器开箱即用，代码量少一半以上；同时单独引入 `spring-security-crypto` 复用成熟的 BCrypt 实现，做到"只取所需"。

**Q：BCrypt 和 MD5 加密密码有什么区别？**
A：MD5 是哈希不是加密，且无盐、速度快，容易被彩虹表破解；BCrypt 自带随机盐且内置 cost 因子可调节计算耗时，抗暴力破解能力强得多。

**Q：前后端分离如何解决跨域？**
A：开发环境用 Vite devServer 的 proxy 转发（浏览器只与同源的前端服务通信）；生产环境用 Nginx 把前端静态资源与 `/api` 挂在同一域名下，从根源消除跨域。

**Q：统一响应结构有什么好处？**
A：前端拦截器一处代码处理所有接口的成功/失败；后端异常不会以堆栈形式泄露给前端；业务错误码与 HTTP 状态码解耦，便于扩展。
