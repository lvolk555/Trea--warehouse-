## 2. 测试环境搭建

### 怎么搭建
- 沙箱环境无 MySQL，安装 **MariaDB 10.11**（MySQL 协议兼容）作为测试数据库；
- 导入 `backend/sql/init.sql`（含建表 + 种子数据：5 个用户、3 门课程、5 道题、积分规则等）；
- `mvn package` 打包后 `java -jar` 启动后端，日志重定向到文件便于排查。

### 踩坑：JDBC 字符集参数错误
首次启动后所有接口返回 500，日志定位到：

```
Caused by: com.mysql.cj.exceptions.WrongArgumentException: Unsupported character encoding 'utf8mb4'
```

**原因**：`application.yml` 中 JDBC URL 写了 `characterEncoding=utf8mb4`。`utf8mb4` 是 MySQL 侧的字符集名，不是 Java 字符集名；Connector/J 9.x 对该参数做严格校验，直接拒绝连接。

**修复**：改为 `characterEncoding=UTF-8`（Java 侧编码名），MySQL 侧的 utf8mb4 由连接默认协商保证。

### 踩坑：Maven 无法直连中央仓库
沙箱出网走代理（`127.0.0.1:18080`），Maven 默认不走环境变量代理，打包时下载 surefire 插件超时。解决：编写 `maven-settings.xml` 显式配置 `<proxies>`，用 `mvn -s maven-settings.xml package` 打包。

## 4. 并发防超扣验证（重点）

### 测试设计
将 student3 余额设为 900（课程需 800），**10 个线程同时发起兑换**，验证：
1. 仅 1 次成功；
2. 余额不为负；
3. 余额恰好剩 100（900 - 800）。

### 结果
```
[PASS] 10 并发兑换仅 1 次成功
[PASS] 并发后余额不为负
[PASS] 并发后余额恰好扣 800
```

### 面试问答
**Q：怎么测试并发扣积分不会超扣？**
A：我写了并发用例：把余额设为 900（商品 800），10 个线程同时调兑换接口，断言只有 1 次成功、余额恰好剩 100。能通过的根因是扣减用的是条件 UPDATE（`WHERE balance >= cost`），InnoDB 行锁把并发请求串行化，第一个扣成功后余额变 100，后续请求条件不满足、受影响行数为 0，事务回滚。如果代码是"先查余额再扣"，这个用例必然出现多次成功或负余额。

## 7. 第二轮扩展测试：管理链路与降级容错

第一轮聚焦学生核心链路，第二轮补齐**管理端操作流**与**异常环境下的降级行为**，共 60 个用例。

### 7.1 课程全生命周期（教师创建 → 管理审核 → 上下架 → 删除）

验证课程状态机 `待审核(0) → 上架(1) → 下架(2)` 的完整流转：

| 用例 | 预期 |
|------|------|
| 教师创建课程（含章节视频） | 成功，初始状态为待审核(0) |
| 已在审核中重复提交 | 拒绝 |
| 管理员审核通过 | 状态变为上架(1) |
| 对非待审核课程审核 | 拒绝 |
| 管理员下架 / 重新上架 | 状态正确切换 |
| 下架课程不在学生广场 | 广场查询不可见 |
| 编辑已上架课程 | 回到待审核(0)，需重新审核 |
| 审核驳回 | 状态变为下架(2) |
| 删除无人选课的下架课程 | 成功 |

**设计要点**：已上架课程被编辑后自动回到待审核状态，保证内容变更必须重新经过管理员审核，防止教师绕过审核直接修改线上内容。

### 7.2 题库 / 公告 / 评论 / 用户 / 积分规则 CRUD

- **题库 CRUD**：新增、编辑、分页筛选、删除，以及缺题干校验、删除不存在题目被拒；
- **公告管理**：新建即发布（产品设计）、学生端可见性、置顶、撤回、删除、缺标题校验；
- **评论审核**：学生发评论进入待审核(0)→ 学生不可见 → 管理员审核通过(1)→ 学生可见 → 隐藏(2)→ 删除；
- **用户管理**：分页、按角色筛选、禁用/启用、调整角色；
- **积分规则配置**：修改积分值、禁用/启用规则、修改不存在规则被拒。

### 7.3 降级与容错（重点）

| 用例 | 验证点 |
|------|--------|
| **禁用用户登录被拒** | 管理员禁用后，该用户无法登录；启用后恢复 |
| **登出后 token 失效** | 登出再用旧 token 访问返回 401 |
| **AI 未配置 API Key 降级** | 提问返回友好降级提示而非报错，会话仍正常创建 |
| **AI 出题未配置报错** | 教师 AI 出题在无 Key 时明确报错 |

**面试问答**
**Q：第三方 AI 服务没配置或挂了怎么办？**
A：我做了降级兜底。`ZhipuAiClient.isConfigured()` 判断 API Key 是否配置：答疑接口未配置时返回友好提示文案并正常落库会话，不抛异常阻断用户；出题/批改这类强依赖接口则明确报错提示管理员配置。调用失败时用 `onErrorResume` 捕获，返回"服务暂时不可用"而不是把异常透传给前端。这样 AI 作为增值功能，其故障不会影响主学习链路。

### 7.4 第二轮踩坑记录

| 问题 | 现象 | 解决 |
|------|------|------|
| URL 中文参数未编码 | 课程广场按中文关键词查询时 `UnicodeEncodeError` | 用 `urllib.parse.urlencode` 编码查询参数 |
| 误判公告默认状态 | 断言"新建公告学生不可见"失败 | 核实代码：新建公告默认即发布，修正断言为"立即可见" |

## 8. 第三轮：模拟用户操作测试（浏览器 UI 测试）

前两轮是接口层测试，第三轮用浏览器自动化模拟真实用户操作，验证**页面渲染、交互流程、前后端联调**，覆盖学生端、管理端（管理员）、管理端（教师）三个视角。

### 8.1 发现并修复的高危缺陷：Naive UI 未全局注册

**现象**：学生端登录页表单完全空白，控制台报 `Failed to resolve component: n-input / n-form`，点击登录报 `formRef.value.validate is not a function`，**整个学生端不可用**。

**原因**：`main.js` 只注册了 Pinia 和 Router，漏掉了 `app.use(naive)`。Naive UI 组件以 `n-` 前缀在模板中使用，未全局注册时 Vue 无法解析这些组件标签。

**修复**：

```javascript
import naive from 'naive-ui'
// ...
app.use(naive)
```

**面试问答**
**Q：组件库引入后页面组件不显示、报 Failed to resolve component，怎么排查？**
A：这是组件未注册的典型症状。先确认引入方式：全量引入要在入口 `app.use(组件库)`；按需引入要配 unplugin 自动导入插件或手动 import 注册。我遇到的就是漏了 `app.use(naive)`。这类问题在构建阶段不会报错（模板编译只是警告），只有运行时才暴露，所以**必须做浏览器端的冒烟测试**，不能只靠接口测试和构建通过来保证质量。
