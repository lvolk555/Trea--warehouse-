## 一、课程概述

### 1.1 课程目标

本课程将带领你从零开始设计一个完整的新零售平台数据库，涵盖商品管理、客户管理、订单管理、员工管理、进销存管理等核心模块。

### 1.2 设计原则

在设计新零售数据库时，我们需要遵循以下原则：

1. **立足业务需求**：数据表设计必须紧密结合实际业务场景
2. **可扩展性**：考虑未来业务发展的需求
3. **数据一致性**：确保数据在不同表之间的关联正确
4. **查询效率**：合理设计索引，优化查询性能
5. **规范化**：遵循数据库设计范式，减少数据冗余

### 1.3 数据库环境准备

- **数据库类型**：MySQL 5.7+
- **客户端工具**：Navicat（或其他MySQL客户端）
- **数据库命名**：`neti`（New Retail的缩写）

```sql
-- 创建数据库
CREATE DATABASE neti CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

## 二、核心概念解析

### 2.1 什么是SPU？

#### 2.1.1 SPU的定义

**SPU**（Standard Product Unit）：标准化产品单元，是商品信息聚合的最小单位。

#### 2.1.2 SPU的特点

- SPU描述的是**一类商品**的共有属性
- 同一SPU的商品具有相同的属性参数
- SPU是抽象的概念，不是具体的可售商品

#### 2.1.3 SPU示例

以"华为nova手机"为例：
- **SPU名称**：华为nova手机
- **品牌**：华为
- **分类**：手机
- **品类**：智能手机
- **共有参数**：屏幕尺寸、摄像头像素、电池容量等

> **注意**：SPU不包含具体的配置信息（如颜色、内存大小等），这些是SKU层面的属性。

---

### 2.2 什么是SKU？

#### 2.2.1 SKU的定义

**SKU**（Stock Keeping Unit）：库存量单位，是物理上不可分割的最小存货单元。

#### 2.2.2 SKU的特点

- SKU是**具体的商品**，可以直接售卖
- 每个SKU都有唯一的标识
- SKU包含具体的属性组合（颜色、配置、版本等）
- SKU与库存直接关联

#### 2.2.3 SKU示例

以华为nova手机为例，以下是不同的SKU：

| SKU编号 | 配置方案 | 颜色 | 内存 | 价格 |
|---------|----------|------|------|------|
| SKU001 | 4G全网通+官方标配 | 幻夜黑 | 6+128G | ¥2999 |
| SKU002 | 4G全网通+官方标配 | 极光蓝 | 6+128G | ¥2999 |
| SKU003 | 4G全网通+官方标配 | 幻夜黑 | 8+256G | ¥3499 |

#### 2.2.4 SKU与库存的关系

**重要设计原则**：

1. **单店场景**：如果只有一个店铺，可以直接在SKU表中添加库存字段
2. **多店/多仓库场景**：需要创建SKU与仓库的关联表来管理库存

```
场景示例：
- 北京某连锁店：SKU001库存500件
- 上海某连锁店：SKU001库存270件
- 同一SKU在不同门店的库存是独立的
```

## 三、商品模块数据表设计

### 3.1 品类和参数表设计

#### 3.1.1 品类表（t_spec_group）

品类用于定义一类商品的共有参数模板。

**表结构**：

| 字段名 | 数据类型 | 约束 | 说明 |
|--------|----------|------|------|
| spg_id | INT UNSIGNED | PRIMARY KEY, AUTO_INCREMENT | 品类ID（主键） |
| spg_name | VARCHAR(50) | NOT NULL, UNIQUE | 品类名称 |

**SQL语句**：

```sql
CREATE TABLE t_spec_group (
    spg_id INT UNSIGNED PRIMARY KEY AUTO_INCREMENT COMMENT '品类ID',
    spg_name VARCHAR(50) NOT NULL COMMENT '品类名称',
    UNIQUE KEY unq_spg_name (spg_name)
) COMMENT '品类表';
```

#### 3.1.2 参数表（t_spec_param）

参数表用于定义每个品类下的具体参数。

**表结构**：

| 字段名 | 数据类型 | 约束 | 说明 |
|--------|----------|------|------|
| spp_id | INT UNSIGNED | PRIMARY KEY, AUTO_INCREMENT | 参数ID |
| spg_id | INT UNSIGNED | NOT NULL, INDEX | 品类ID（外键） |
| spp_name | VARCHAR(50) | NOT NULL | 参数名称 |
| spp_unit | VARCHAR(20) | NULL | 参数单位 |
| is_key | TINYINT(1) | NOT NULL DEFAULT 0 | 是否关键参数 |
| is_sale | TINYINT(1) | NOT NULL DEFAULT 0 | 是否销售属性 |

**SQL语句**：

```sql
CREATE TABLE t_spec_param (
    spp_id INT UNSIGNED PRIMARY KEY AUTO_INCREMENT COMMENT '参数ID',
    spg_id INT UNSIGNED NOT NULL COMMENT '品类ID',
    spp_name VARCHAR(50) NOT NULL COMMENT '参数名称',
    spp_unit VARCHAR(20) COMMENT '参数单位',
    is_key TINYINT(1) NOT NULL DEFAULT 0 COMMENT '是否关键参数(0否1是)',
    is_sale TINYINT(1) NOT NULL DEFAULT 0 COMMENT '是否销售属性(0否1是)',
    INDEX idx_spg_id (spg_id)
) COMMENT '参数表';
```

**关键参数 vs 销售属性**：

- **关键参数**：用于商品筛选和对比（如屏幕尺寸、电池容量）
- **销售属性**：影响SKU生成的属性（如颜色、内存大小）

### 3.2 品牌和分类关系设计

#### 3.2.1 品牌表（t_brand）

**表结构**：

| 字段名 | 数据类型 | 约束 | 说明 |
|--------|----------|------|------|
| brand_id | INT UNSIGNED | PRIMARY KEY, AUTO_INCREMENT | 品牌ID |
| brand_name | VARCHAR(50) | NOT NULL, UNIQUE | 品牌名称 |
| brand_image | VARCHAR(200) | NULL | 商标图片路径 |
| brand_letter | CHAR(1) | NOT NULL | 品牌首字母 |

**SQL语句**：

```sql
CREATE TABLE t_brand (
    brand_id INT UNSIGNED PRIMARY KEY AUTO_INCREMENT COMMENT '品牌ID',
    brand_name VARCHAR(50) NOT NULL COMMENT '品牌名称',
    brand_image VARCHAR(200) COMMENT '商标图片路径',
    brand_letter CHAR(1) NOT NULL COMMENT '品牌首字母',
    UNIQUE KEY unq_brand_name (brand_name),
    INDEX idx_brand_letter (brand_letter)
) COMMENT '品牌表';
```

**设计要点**：
- 图片存储：不直接存储图片文件，只存储文件路径
- 首字母索引：便于用户按字母快速查找品牌

#### 3.2.2 分类表（t_category）

**表结构**：

| 字段名 | 数据类型 | 约束 | 说明 |
|--------|----------|------|------|
| cate_id | INT UNSIGNED | PRIMARY KEY, AUTO_INCREMENT | 分类ID |
| cate_name | VARCHAR(50) | NOT NULL | 分类名称 |
| parent_id | INT UNSIGNED | NOT NULL DEFAULT 0 | 父分类ID（0表示顶级分类） |
| level | TINYINT UNSIGNED | NOT NULL | 分类层级 |

**SQL语句**：

```sql
CREATE TABLE t_category (
    cate_id INT UNSIGNED PRIMARY KEY AUTO_INCREMENT COMMENT '分类ID',
    cate_name VARCHAR(50) NOT NULL COMMENT '分类名称',
    parent_id INT UNSIGNED NOT NULL DEFAULT 0 COMMENT '父分类ID',
    level TINYINT UNSIGNED NOT NULL COMMENT '分类层级',
    INDEX idx_parent_id (parent_id)
) COMMENT '分类表';
```

#### 3.2.3 品牌与分类关联表（t_brand_category）

一个品牌可以属于多个分类，一个分类可以有多个品牌，需要关联表。

```sql
CREATE TABLE t_brand_category (
    brand_id INT UNSIGNED NOT NULL COMMENT '品牌ID',
    cate_id INT UNSIGNED NOT NULL COMMENT '分类ID',
    PRIMARY KEY (brand_id, cate_id)
) COMMENT '品牌分类关联表';
```

### 3.3 产品表和商品表设计

#### 3.3.1 产品表（t_product）

产品表对应SPU概念，描述一类商品的共有信息。

**表结构**：

| 字段名 | 数据类型 | 约束 | 说明 |
|--------|----------|------|------|
| prod_id | INT UNSIGNED | PRIMARY KEY, AUTO_INCREMENT | 产品ID |
| prod_title | VARCHAR(100) | NOT NULL | 产品标题 |
| prod_subtitle | VARCHAR(200) | NULL | 产品副标题 |
| cate_id | INT UNSIGNED | NOT NULL, INDEX | 分类ID |
| brand_id | INT UNSIGNED | NULL, INDEX | 品牌ID（NULL表示无品牌） |
| spg_id | INT UNSIGNED | NOT NULL, INDEX | 品类ID |
| is_saleable | TINYINT(1) | NOT NULL DEFAULT 1 | 是否上架 |
| is_valid | TINYINT(1) | NOT NULL DEFAULT 1 | 是否有效 |
| create_time | TIMESTAMP | NOT NULL DEFAULT CURRENT_TIMESTAMP | 创建时间 |
| update_time | TIMESTAMP | NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP | 更新时间 |

**SQL语句**：

```sql
CREATE TABLE t_product (
    prod_id INT UNSIGNED PRIMARY KEY AUTO_INCREMENT COMMENT '产品ID',
    prod_title VARCHAR(100) NOT NULL COMMENT '产品标题',
    prod_subtitle VARCHAR(200) COMMENT '产品副标题',
    cate_id INT UNSIGNED NOT NULL COMMENT '分类ID',
    brand_id INT UNSIGNED COMMENT '品牌ID',
    spg_id INT UNSIGNED NOT NULL COMMENT '品类ID',
    is_saleable TINYINT(1) NOT NULL DEFAULT 1 COMMENT '是否上架(0否1是)',
    is_valid TINYINT(1) NOT NULL DEFAULT 1 COMMENT '是否有效(0否1是)',
    create_time TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    update_time TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    INDEX idx_cate_id (cate_id),
    INDEX idx_brand_id (brand_id),
    INDEX idx_spg_id (spg_id)
) COMMENT '产品表';
```

**设计要点**：

1. **is_saleable（是否上架）**：控制产品是否在前台展示
2. **is_valid（是否有效）**：标记产品是否被删除（逻辑删除）
   - 示例：某款风衣去年热销，今年过时不再进货，设置is_valid=0
   - 为什么不物理删除？保留历史数据，便于统计分析

#### 3.3.2 商品表（t_sku）

商品表对应SKU概念，是具体的可售商品。

**表结构**：

| 字段名 | 数据类型 | 约束 | 说明 |
|--------|----------|------|------|
| sku_id | INT UNSIGNED | PRIMARY KEY, AUTO_INCREMENT | 商品ID |
| prod_id | INT UNSIGNED | NOT NULL, INDEX | 产品ID（外键） |
| sku_title | VARCHAR(100) | NOT NULL | 商品标题 |
| sku_images | JSON | NULL | 商品图片（JSON数组） |
| sku_price | DECIMAL(10,2) | NOT NULL | 商品价格 |
| sku_params | JSON | NOT NULL | 参数规格（JSON格式） |
| sku_status | TINYINT UNSIGNED | NOT NULL DEFAULT 1 | 商品状态 |
| create_time | TIMESTAMP | NOT NULL DEFAULT CURRENT_TIMESTAMP | 创建时间 |
| update_time | TIMESTAMP | NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP | 更新时间 |

**SQL语句**：

```sql
CREATE TABLE t_sku (
    sku_id INT UNSIGNED PRIMARY KEY AUTO_INCREMENT COMMENT '商品ID',
    prod_id INT UNSIGNED NOT NULL COMMENT '产品ID',
    sku_title VARCHAR(100) NOT NULL COMMENT '商品标题',
    sku_images JSON COMMENT '商品图片JSON数组',
    sku_price DECIMAL(10,2) UNSIGNED NOT NULL COMMENT '商品价格',
    sku_params JSON NOT NULL COMMENT '参数规格JSON',
    sku_status TINYINT UNSIGNED NOT NULL DEFAULT 1 COMMENT '商品状态',
    create_time TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    update_time TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    INDEX idx_prod_id (prod_id)
) COMMENT '商品表';
```

**数据示例**：

产品表数据：
```

cate_id: 3 (手机分类)
```

### 3.4 商品库存设计

#### 3.4.1 库存设计的挑战

**简单方案（单店场景）**：
- 在SKU表中添加stock字段
- 适用于只有一个店铺的情况

**复杂方案（多店/多仓库场景）**：
- 需要设计仓库表和库存关联表
- 适用于连锁零售、多仓库配送等场景

#### 3.4.2 仓库表（t_warehouse）

```sql
CREATE TABLE t_warehouse (
    wh_id INT UNSIGNED PRIMARY KEY AUTO_INCREMENT COMMENT '仓库ID',
    city_id INT UNSIGNED NOT NULL COMMENT '城市编号',
    wh_address VARCHAR(200) NOT NULL COMMENT '仓库地址',
    wh_tel VARCHAR(20) COMMENT '联系电话',
    INDEX idx_city_id (city_id)
) COMMENT '仓库表';
```

#### 3.4.3 仓库与商品关联表（t_warehouse_sku）

```sql
CREATE TABLE t_warehouse_sku (
    wh_id INT UNSIGNED NOT NULL COMMENT '仓库ID',
    sku_id INT UNSIGNED NOT NULL COMMENT '商品ID',
    stock INT UNSIGNED NOT NULL DEFAULT 0 COMMENT '库存数量',
    warning_stock INT UNSIGNED NOT NULL DEFAULT 10 COMMENT '预警库存',
    PRIMARY KEY (wh_id, sku_id)
) COMMENT '仓库商品库存表';
```

#### 3.4.4 零售店表（t_shop）

```sql
CREATE TABLE t_shop (
    shop_id INT UNSIGNED PRIMARY KEY AUTO_INCREMENT COMMENT '店铺ID',
    city_id INT UNSIGNED NOT NULL COMMENT '城市编号',
    shop_name VARCHAR(50) NOT NULL COMMENT '店铺名称',
    shop_address VARCHAR(200) NOT NULL COMMENT '店铺地址',
    shop_tel VARCHAR(20) COMMENT '联系电话',
    INDEX idx_city_id (city_id)
) COMMENT '零售店表';
```

#### 3.4.5 零售店与商品关联表（t_shop_sku）

```sql
CREATE TABLE t_shop_sku (
    shop_id INT UNSIGNED NOT NULL COMMENT '店铺ID',
    sku_id INT UNSIGNED NOT NULL COMMENT '商品ID',
    stock INT UNSIGNED NOT NULL DEFAULT 0 COMMENT '库存数量',
    PRIMARY KEY (shop_id, sku_id)
) COMMENT '店铺商品库存表';
```

## 五、订单与物流模块

### 5.1 订单表设计

#### 5.1.1 订单表（t_order）

```sql
CREATE TABLE t_order (
    order_id INT UNSIGNED PRIMARY KEY AUTO_INCREMENT COMMENT '订单ID',
    order_code VARCHAR(50) NOT NULL COMMENT '订单流水号',
    cust_id INT UNSIGNED NOT NULL COMMENT '客户ID',
    shop_id INT UNSIGNED COMMENT '店铺ID（实体店订单）',
    type TINYINT UNSIGNED NOT NULL COMMENT '销售方式(1实体店2线上)',
    amount DECIMAL(10,2) UNSIGNED NOT NULL COMMENT '商品总金额',
    actual_amount DECIMAL(10,2) UNSIGNED NOT NULL COMMENT '实际支付金额',
    coupon_id INT UNSIGNED COMMENT '使用的购物券ID',
    freight DECIMAL(10,2) UNSIGNED COMMENT '运费',
    weight DECIMAL(8,2) UNSIGNED COMMENT '商品总重量(kg)',
    pay_type TINYINT UNSIGNED COMMENT '支付方式',
    status TINYINT UNSIGNED NOT NULL COMMENT '订单状态',
    receiver_name VARCHAR(50) COMMENT '收货人姓名',
    receiver_tel VARCHAR(11) COMMENT '收货人电话',
    receiver_address VARCHAR(200) COMMENT '收货地址',
    remark VARCHAR(500) COMMENT '订单备注',
    create_time TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    pay_time TIMESTAMP COMMENT '支付时间',
    deliver_time TIMESTAMP COMMENT '发货时间',
    receive_time TIMESTAMP COMMENT '收货时间',
    UNIQUE KEY unq_order_code (order_code),
    INDEX idx_cust_id (cust_id),
    INDEX idx_shop_id (shop_id),
    INDEX idx_type (type),
    INDEX idx_status (status),
    INDEX idx_create_time (create_time)
) COMMENT '订单表';
```

**订单状态说明**：

| 状态值 | 状态名称 | 说明 |
|--------|----------|------|
| 0 | 待支付 | 订单已创建，等待付款 |
| 1 | 已支付 | 支付成功，等待发货 |
| 2 | 已发货 | 商品已发出 |
| 3 | 已收货 | 客户已确认收货 |
| 4 | 已完成 | 订单完成 |

### 8.2 设计最佳实践

#### 8.2.1 命名规范

1. **表名**：使用`t_`前缀，小写字母，下划线分隔
   - 示例：`t_order`、`t_customer`

2. **字段名**：小写字母，下划线分隔
   - 示例：`cust_id`、`create_time`

3. **索引名**：
   - 普通索引：`idx_字段名`
   - 唯一索引：`unq_字段名`

4. **外键字段**：关联表名 + `_id`
   - 示例：`cust_id`、`sku_id`

#### 8.2.2 字段设计原则

1. **主键**：统一使用`INT UNSIGNED AUTO_INCREMENT`
2. **状态字段**：使用`TINYINT UNSIGNED`，并添加注释说明各值的含义
3. **金额字段**：使用`DECIMAL(10,2) UNSIGNED`，确保精度
4. **时间字段**：
   - 创建时间：`create_time TIMESTAMP DEFAULT CURRENT_TIMESTAMP`
   - 更新时间：`update_time TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP`
5. **JSON字段**：用于存储变长数组或对象（如图片列表、参数规格）

#### 8.2.3 索引设计原则

1. **主键自动创建索引**
2. **外键字段创建索引**：提高关联查询效率
3. **查询条件字段创建索引**：如状态、类型等
4. **唯一约束字段创建索引**：如手机号、订单号等
5. **避免过多索引**：影响写入性能

#### 8.2.4 关联关系设计

| 关系类型 | 实现方式 | 示例 |
|----------|----------|------|
| 一对一 | 共享主键或唯一外键 | 员工-用户 |
| 一对多 | 在多的一方添加外键 | 分类-产品 |
| 多对多 | 创建关联表 | 品牌-分类 |

### 8.3 扩展建议

1. **数据归档**：定期将历史订单数据归档，提高查询性能
2. **读写分离**：高并发场景下考虑数据库读写分离
3. **缓存优化**：热点数据使用Redis缓存
4. **分库分表**：数据量巨大时考虑分库分表策略
5. **数据安全**：敏感数据加密存储，定期备份
